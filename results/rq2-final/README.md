# RQ2 最终结果汇总

**最终方案：agent 不筛选 + judge v3。在 test 的 250 条承诺上判对 210 条，准确率 0.840（95% 区间 0.792–0.884），基线 hybrid + v2 是 0.768。**

RQ2 的问题：公司在报告里做了带截止年份的承诺，后续报告说明它达成（achieved）、失败（failed）、说不清（unclear），还是再没提过（disappeared）？

## 系统怎么工作

1. **固定检索：** 在承诺之后、截止年次年之前的报告里，按年份分配名额（截止年后第一份报告 6 条，更晚的每份 3 条，更早的每份 2 条），再加最佳命中的相邻句。
2. **固定补搜：** 专门搜一次改期、推迟的表述。
3. **LLM 规划：** 模型看已有证据，判断还缺什么，决定是否补搜或翻相邻句、整页，最多 2 轮。总证据不超过 20 条。
4. **judge v3 判定：** 模型给每条证据打标签，固定规则算出结论；判 3 次，取严格多数。

模型：`gpt-5.6-luna`（reasoning effort low）、`text-embedding-3-small`。知识库：240 份报告，108,376 条句子（哈希 `d8a62bfe40c6`）。

### 最终方案的细节

| 结论 | 精确率 | 召回率 | 标准答案条数 |
|---|---|---|---|
| achieved | 0.93 | 0.92 | 145 |
| failed | 0.80 | 0.82 | 34 |
| unclear | 0.70 | 0.72 | 64 |
| disappeared | 0.40 | 0.29 | 7 |

- 按标注来源：组内人工标注 115 条，准确率 0.826；模型标注 135 条，准确率 0.852。
- 投票稳定性：250 条里有 37 条在 3 次判定中结果不一致。
- 规划行为：平均每条调用 1.27 次；250 条里只有 9 条用满 2 轮；19% 的证据来自固定检索之后。
- 检索延迟：中位 5.2 秒，P95 10.5 秒（8 线程并行，且有其他运行共用机器，只能作粗略参考）。

### 配对比较（McNemar，未校正）

| 比较 | 判对 | 多对 / 多错 | p |
|---|---|---|---|
| 基线 hybrid + v2 → 最终方案 | 192 → 210 | +32 / −14 | 0.011 |
| 固定预算 + v3 → 最终方案 | 202 → 210 | +13 / −5 | 0.096 |
| hybrid + v3 → 最终方案 | 204 → 210 | +19 / −13 | 0.38 |
| 同样 agent 证据，v2 → v3 | 196 → 210 | +25 / −11 | 0.029 |

## 主要发现

1. **judge v3 贡献最明确：** 三种证据换成 v3 后，都多判对 11 到 14 条。代价是过度判定略增。
2. **LLM 规划没有被证明有帮助：** 都用 v2 时，agent 对 hybrid 是 +16/−12（p=0.57），对固定预算是 +18/−13（p=0.47）。最终方案分数最高，但很大一部分提升来自 v3。
3. **筛选新证据没有用：** 只保留 judge 用得上的新证据，反而从 210 条降到 202 条，成本接近翻倍。
4. **检索不是主要瓶颈：** dev 上能核对的错判里，多数答案已被检索到；证据加倍到 40 条，准确率还下降了。

## 引用这些结果时要注意

- **最终方案是看完 test 后选定的。** 事先冻结的主方案是 agent + 筛选（0.808，对基线 p=0.18，不显著）。0.840 是七组里的最高分，没有独立验证，所以 p=0.011 不能当作确证；七组两两比较校正后约为 0.23。报告里应说明这一点。
- **事先冻结的 8 个比较都没有达到 p<0.05。**
- **v3 的提升主要在模型标注的数据上。** 只看组内人工标注的 115 条：hybrid 87→88，固定预算 92→91，agent 89→95。
- **v3 是看过 dev 错判后设计的，也没有单独的人工核查。** dev 上的数字（`summary.csv`）偏乐观，应以 test 为准。
- **RQ2 的 test 已用完。** 之后如果再改系统，就不能再用它验证了。
- **系统读不到 5 词以下的短句**（约 1,900 条，比如表格里的 “Achieved”）。
- **graph 和 finder 没有在 test 上跑**，无法和它们配对比较。
- **RQ1 还没有跑 test，这里不包含 RQ1 结果。**

## 复现最终方案

```bash
uv run gw-eval --task rq2 --system agentic-rag --split test --repeats 3 --judge v3
```

规划默认 2 轮。这条命令会把 test 再判一遍，且模型每次采样不同，分数会有小幅波动；并行检索可设 `GW_RETRIEVAL_WORKERS=8`。本次的运行编号是 `20261031T085145Z`（检索）和 `20261031T091030Z`（v3 判定）。
